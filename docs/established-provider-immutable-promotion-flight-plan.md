# Established dark provider image promotion — Tier 2

This source prerequisite updates only the image of an already established sole
production provider app. It does not create the missing foundation or activate
Session Prep, and is not a beta-completion checkpoint. Existing dual workflows,
bootstrap, public/staging/Core/Scribe configuration and all-false pair preparation
remain unchanged.

Before a founder-only manual run, separately provision the protected, dedicated
promotion client and Core artifact-read token. The client requires the reviewed
provider metadata/image-update and fixed Core runtime-read capabilities plus
existing KV/registry/managed-identity/role and Graph membership metadata reads;
new variable names do not prove least privilege. No permissions are provisioned
here. Keep legacy deployment and this new default-off latch off until that
separate decision. Core source must include the exact reviewed PR902 lineage on
current master, with accepted completed prepare/promote runtime evidence. The
provider producer must authenticate a completed candidate from current main.

The consumer requires the actual sole healthy dark provider app, exact public
platform authority profile, managed identity/registry/versionless secret refs,
retained immutable old and candidate manifests, and matching HTTPS Core panel.
It re-admits provider/source/foundation before the only digest image update and
checks fresh authenticated compatible Core facts immediately before and after.
Healthy replica replacement/scaling is allowed; every fresh sample still proves
readiness. Public hashes contain only explicit public values and reference facts,
never erased/private values. Samples are not atomic or full secret equality.

Failure before update performs no deployment. Failure after update emits no
success receipt and performs no automatic rollback. Retain the prior healthy
digest as image-only undo evidence; an operator must independently verify the
compatible recovery pair before any separately authorized recovery. A receipt
cannot authorize activation. Validate required configuration, schema/TLS, Entra
caller/role, provider origin/TLS and a compatible recovery pair separately, then
complete live clinical staging acceptance before beta activation.

Source/mocked tests do not prove actual Azure permissions, foundation existence,
registry retention, Core artifacts, production connections or clinical behavior.
The observed production provider resource group is absent; establish it through
the existing full reviewed foundation path before this consumer can run.
