# Accepted reviewed-source display (Tier 2)

The new display bridge reads Core's successful final receipt projection. Fresh
read 1.1 can attach links to the exact just-accepted answer; separate retained
read 1.2 restores old answers and original ordinal maps as historical or
superseded. Neither display route is used by context reads, models or inference.
No browser record selector, current note lookup, source URL or model citation
can create a link. Core independently authorizes each retained citation read.

Release Core receiver/display first, then the provider read bridge and the
byte-pinned Core browser consumer. Missing support retains the old panel's
history behavior. The new panel fails closed on malformed supported display,
keeps useful canonical answers without unverified links, and suppresses
attributed export when the accepted map cannot be verified. Record changes and
authority loss cancel and discard old requests and bytes. No schema/flag change
or production activation is part of this source proposal.

`app/panel.js` is the readable source. The optional `/embed/v1/panel.delivery.js`
route serves separately generated delivery bytes for normal script/SRI loading.
`tools/build_panel_delivery.mjs <exact locked Core web runtime> write|check`
uses esbuild 0.25.12 from the verified package/lock, records the actual committed
input/blob/options and verifies regenerated output. Existing readable/versioned
and compatibility delivery routes remain byte-identical to each other. Old
content-addressed Core assets remain available. All generated files count in
the change budget; this is one complete source outcome, not split PRs.

Source-only transport, contract and real DOM regressions qualify ordering,
same-day identical text, reload, export, supersession, current-owner denial and
late request suppression. They do not prove live acceptance or vendor behavior.
Normal final-head CI, independent review, full release provenance and explicit
staging acceptance remain necessary. Recovery is the prior pinned browser asset
and provider source; retained maps remain server-owned under the old freshness
and owner guards.
